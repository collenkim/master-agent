code-agent 업데이트

원격 변경 받기 → 의존성 설치 → 빌드·테스트 → 등록 프로젝트 적용. 작업·승인 진행 중인 프로젝트는 건너뜁니다.

건너뜀 사유는 code-agent의 업데이트 가능 여부 조회 결과입니다. 현재 브랜치의 작업 조회와 달리 다른 브랜치의 미완료 작업도 업데이트를 막을 수 있습니다. 저장된 작업 상태이며 프로세스 실행 여부를 뜻하지 않습니다.

프로젝트

단계별 타임라인

상태 관측·code-agent 이벤트·요청함 변화를 최신 수집 순으로 표시합니다. 제어 연결이 없는 프로젝트는 상태 관측만 수집하며, 조회 사이에 지나간 단계는 복원할 수 없습니다. 브랜치 전환은 이전 작업의 완료를 뜻하지 않습니다.

목표별 진행

저장된 master 실행 기록
현재 DB에 등록된 로컬 프로젝트를 표시합니다. code-agent 상태 조회는 프로세스 생존 확인을 보장하지 않습니다.

code-agent 일괄 업데이트

원격 업데이트는 설치 소스의 추적 브랜치를 격리 사본에서 pull하고 npm 설치·빌드·테스트 스크립트를 실행합니다. 검증 실패 시 프로젝트에 적용하지 않습니다. 원본 소스의 미커밋 변경은 포함하지 않습니다.

code-agent가 미완료 작업을 보고하면 건너뜁니다. 현재 브랜치에 작업이 없어도 다른 브랜치에 보관된 작업이 사유에 포함될 수 있습니다. 해당 프로젝트에서 작업의 완료·중단 상태를 먼저 확인하세요.

서비스 그룹 만들기

소속 프로젝트

새 프로젝트는 그룹 저장 시 함께 등록됩니다. 취소하면 입력한 새 프로젝트도 저장되지 않습니다.

프로젝트를 제외해도 이미 접수한 요청의 대상은 바뀌지 않습니다.

빈 그룹을 만듭니다. 저장 후 구성 편집에서 프로젝트를 추가하세요.

추가 설정

대시보드가 실행 중인 PC의 기존 폴더를 등록합니다. 요청 시 기본 근거를 수집하고 설치·연결을 점검합니다. 부족한 준비는 공통 요청함에서 안내합니다.

code-agent 제어 연결


    

    
이 PC가 신뢰한 대시보드 키로 code-agent에 연결을 요청합니다. 연결 후 이 대시보드가 실행을 맡기고 관측합니다. 승인·위임 권한은 바뀌지 않습니다.

    
토큰과 PC 신뢰 키는 화면·DB에 저장하지 않습니다. DB에는 code-agent가 만든 토큰 파일 경로만 남습니다.

    
    

    

  

  

    
PC 신뢰

    

    

    
PC당 한 번 합니다. code-agent가 이 PC에 신뢰 키를 만들고, 이후 프로젝트마다 제어 연결 확인으로 연결합니다. 개인 키는 화면·DB에 남지 않습니다.

    
    

    

  

  

    
프로젝트 삭제

    

    

    

    
대시보드 등록을 해제하고 모든 그룹에서 제외합니다. 자동 조회·새 요청·일괄 업데이트 대상에서도 빠집니다.

    
프로젝트 폴더·소스·설치된 code-agent와 이전 요청·실행 이력은 보존합니다. 다시 등록할 때는 새 프로젝트 ID가 필요합니다.

    
미완료 master-agent 목표나 실행·업데이트 잠금이 있으면 삭제할 수 없습니다.

    

    

  

  

    
그룹 삭제

    

    

    
그룹 목록과 새 요청 대상에서 제외합니다. 소속 프로젝트의 등록·폴더·code-agent는 유지됩니다.

    
이미 접수한 요청은 기존 프로젝트 범위로 계속 진행하며 요청·실행 이력을 보존합니다. 새 그룹을 만들 때는 다른 그룹 ID를 사용하세요.
