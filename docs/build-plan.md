# 첫 구축 작업 계획

이 문서는 실행 계약·상태 관리, 근거 수집·AI 계획 생성, 개발 호스트 연결, 실제 검증·인계·자동 진행의 작업 범위를 기록한다. 승인 위임·자율 복구와 UI는 후속 단계다. 고정된 계획과 모의 실행을 AI 구현 완료로 표현하지 않는다.

## 구현 순서

1. Node.js 24 ESM과 내장 SQLite로 별도 설치 의존성 없는 로컬 실행 기반을 만든다. 저장 계층은 이후 대체할 수 있게 분리한다.
2. 프로젝트의 도메인·구현 범위·기존 계획·근거와 그룹, 목표·완료 조건·대상 스냅샷을 관리한다.
3. 계획의 도메인 배정·참조·의존 관계·검증 조건을 검사하고 판단 기록과 함께 버전을 저장한다.
4. 실행 전에 판단·입력 버전·실행 시도·프로젝트 잠금을 영속 저장한다. 결과는 같은 계획·시도에서만 수용한다.
5. 명시적인 모의 러너로 의존 작업 실행, 실패·재시도, 일시 정지·재개, 재계획과 중단 후 관측 불가를 검증한다.
6. CLI와 code-agent 읽기 전용 상태 조회를 연결한다. 모의 결과와 실제 프로젝트 관측을 구별한다.
7. 입력 검증, 저장 실패, 오래된 판단, 중복 접수, 충돌, 검증 실패와 재시작을 회귀 테스트한다.

## 완료 범위

실행 가능한 CLI, 영속 저장, 프로젝트·그룹 등록, 계획 검증, 판단 후 실행, 모의 다중 프로젝트 시나리오와 테스트를 제공한다. 기존 저장소를 수정하거나 code-agent 승인 경로를 우회하지 않는다. 운영 정책의 수치·자동 복구·배포 환경은 확정하지 않는다.

1단계 판단 정책은 명시적 규칙과 입력 계획으로 검증한다. 실제 개발 실행은 지원 어댑터가 생길 때까지 거부한다.

## 2단계 근거 수집과 AI 계획

1. 지정된 프로젝트 문서·코드를 종류·출처·줄 번호·내용 해시와 함께 수집하고 이전 스냅샷을 보존한다.
2. 수집된 범위에서 검색과 context 구성을 제공하고, 원본 파일 변경을 감지한다.
3. Codex·Claude CLI에 context를 stdin으로 전달해 구조화 분석을 요청한다. 대상 저장소에서 도구를 실행하지 않는다.
4. 요구 인용·완료 조건·프로젝트 평가·실제 근거·배정·의존 관계를 검사한다.
5. 오류와 모호함을 자동 재검토하고 정보 부족·중대한 사람 판단을 구별한다. 현재 질문의 응답을 받아 재분석한다.
6. 판단 기록과 최신 상태 대조 후 계획을 활성화하고 기존 모의 실행 경로에 연결한다.
7. 가짜 모델·CLI 회귀 시험과 합성 자료의 실제 CLI 계획 생성 시험을 분리해 기록한다.

## 3단계 개발 호스트 연결

1. code-agent 상태·기존 승인·세션 임대 계약을 소스에서 대조한다.
2. live 계획의 준비된 작업을 판단·잠금 저장 후 설치된 Claude 호스트에 배정한다.
3. 같은 작업·시도에 호스트 세션과 실행 후 관측을 연결하고 승인 대기·차단·미확인을 구분한다.
4. 현재 상태로 같은 세션을 계속 실행한다. 재시작·오래된 결과로 중복 실행하지 않는다.
5. 자동 완료 판정은 실제 검증 증거와 변경 범위 검증이 구현될 때까지 닫아 둔다.
6. 실제 호스트의 접수 경계 시험과 가짜 프로세스 회귀 검증을 구분한다.

## 실제 검증과 자동 진행

1. 배정 전 정확한 변경 경로·조건별 실행 명령·산출물 연결을 등록한다.
2. 배정 시 Git 기준을 저장하고 승인·변경 범위 대조 후 독립 검증 명령을 실행한다.
3. 테스트 전후 파일과 원격 상태가 같을 때 검증 기록을 봉인하고, 외부 작업 종료 관측 후 인계·잠금을 해제한다.
4. 현재 계획의 후행 작업과 다중 프로젝트 통합 검증을 진행한다. 최종 파일과 조건별 실제 증거로 로컬 목표를 완료한다.
5. drive가 가능한 전이를 반복하되 승인·검증 실패·미확인 상태를 무한 재시도하지 않도록 한다.

## 검증 실패 복구

읽기 전용 분석의 결과 적용 취소와 검증 명령 반환 후 중단 복구를 추가했다. 명령 실행·반환 기록을 분리하고 현재 검증 실행 ID로 오래된 결과와 다음 명령 실행을 차단한다. 세부 경계는 [분석·검증 중단 처리](interruption.md)를 따른다.

실패 로그·현재 코드·기존 계약을 연결한 AI 분석, 잘못된 제안 재검토, 판단 저장 후 동일 세션 수정·재검증을 구현했다. 외부 승인 대기, 추가 근거, 범위 변경, 중대한 사람 결정을 구분한다. 같은 실패의 중복 분석과 한 시도의 반복 실행을 제한한다. 상세 계약은 [자동 복구](recovery.md)에 정리했다.

외부 작업 정리·변경 보존·잠금 해제와 연결한 [재계획 인계](replanning.md)를 구현했다. [반영 기록·관측 복구](delivery-reconciliation.md)로 커밋 내 동의 기록 대조와 호스트 반환 후 재검증 복구를 구현했다. 이후 외부 승인 위임, 취소·일반 중단 복구, 실제 AI·승인을 포함한 전체 시나리오를 검증한다.
