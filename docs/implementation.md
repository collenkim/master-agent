## 실행 경계

웹 등록은 설치 프로젝트 후보 목록에서 선택하거나 직접 입력한 기존 폴더를 카탈로그에 추가한다. 후보는 알려진 작업 위치에서 설치 표시를 확인한 결과이며 중앙 등록부나 전체 디스크 목록이 아니다. 요청 실행기가 기본 근거와 준비 상태를 확인하지만 code-agent 설치·최초 인증·권한을 자동 승인하지 않는다. 대시보드는 실행 터미널을 종료하면 멈추지만 이미 접수한 요청의 별도 실행기는 유지된다. 연결 오류와 화면 기능은 [대시보드](ui.md)를 따른다.

일괄 업데이트의 기본 방식은 설치된 code-agent Git 저장소의 upstream에서 새 버전을 받아 검증한 뒤 적용하는 것이다. 원본 소스는 보존하고 격리 사본에서 pull·npm 설치·빌드·테스트를 수행한다. Git 설치·추적 브랜치가 없으면 원격 업데이트를 거부하며 배포 출처를 추정하지 않는다. 현재 설치본만 적용하는 방식도 제공한다. 준비가 실패하면 프로젝트 적용을 시작하지 않으며 프로젝트를 자동 커밋하지 않는다. 서버 종료는 현재 단계를 기다린 뒤 나머지를 취소한다.

계약 인계는 소스 검사·문서 해시·반영 커밋을 대조하고 후속 담당의 첫 배정 전에 `planning contracts`로 등록한다. 형식과 한도는 [검증 계약](live-verification.md)을 따른다. 실제 개발 호스트는 Claude이며 Codex는 계획·판단 provider로 제공한다.

## 남은 작업

[공통 요청함](dashboard-interactions.md)은 실제 code-agent interaction API에 연결했다. 빈/기존 격리 프로젝트의 단계별 계약·서명·문서 동의 적용과 브라우저 왕복을 확인했다. 시험용 발행자·인증 정보로 수행한 계약 검증이며 두 실제 모델의 전체 업무 완주와는 구분한다. 운영 프로젝트는 사용자가 기존 제어 연결에 사람 채널을 추가해야 한다.

1. 실제 모델의 실패 수정·재계획·프로세스 중단·재부착을 격리 저장소에서 연속 검증한다. 정상 흐름 성공과 자동 회귀만으로 이를 대신하지 않는다.
2. 자유 목표의 AI 계획 생성부터 검증 계약 연결·개발·통합 완료까지 한 번에 실행한다. 현재 전체 흐름 시나리오는 고정 master 계획으로 시작한다.
3. 더 큰 업무 사례와 Codex 개발 호스트로 확장한다. 종료된 독립 세션과 Codex 비대화형 세션의 자동 재개는 code-agent 미지원이다. 질문과 무관한 작업 중지 화면, master 재계획의 수동 채택 UI, 원격 러너·운영 예산·프로젝트 도메인/근거 자동 갱신은 별도 범위다.
4. 설치 이후의 init·doctor·update 명령과 배포 패키징을 보완한다. 현재는 로컬 소스를 npm 전역 명령으로 연결하며 공개 npm·단일 실행 파일 배포는 제공하지 않는다.
5. 단계별 산출물·실행 결과 전문·실시간 로그 상세 화면을 연결한다. 현재 타임라인은 관측 및 발행 이벤트 기반이며, 관측 사이의 모든 단계 시작·완료를 보장하려면 code-agent 이벤트·결과 계약을 추가 확인해야 한다. 실제 프로세스 생존 정보도 상태 관측과 별도로 필요하다.

## code-agent 연동 후속 확인

실제 모델 시험에서 관측한 생성 품질의 확인 항목이다. 현재 설치 지침에는 수락 기준 고유 ID와 리뷰의 `findings`/`checked` 형식이 있으므로, 아래 현상을 곧바로 미구현 결함으로 간주하지 않는다. 최신 빌드의 모델 실행에서 재현되는 항목만 code-agent 수정 대상으로 삼는다.

| 관측한 보정 비용 | 다음 실제 모델 시험의 통과 기준 |
| --- | --- |
| 설계 문서의 수락 기준 ID 중복 | 정의·참조를 구분해 첫 생성에서 FUN-AC 검사 통과 |
| 리뷰 표 뒤 자유 설명으로 형식 오류 | 지적과 확인 근거를 지정된 표 또는 findings/checked JSON으로 반환 |
| 계약 사본의 파일명만 인용 | 저장소 루트 기준 전체 상대 경로로 인용해 DOC-REF 검사 통과 |

근거는 [실제 병렬·계약 인계 검증](verification.md#실제-병렬계약-인계-검증)에 보존한다. 검사를 완화하거나 지적을 누락해 통과시키지 않으며, 계약 등록·담당 입력 해시·답 출처 구분을 유지한다. 공통 요청함의 현재 API와 책임 경계는 [연동 계약](dashboard-interactions.md)을 따른다.
