## 실행 경계

계획 생성의 응답 스키마는 수집한 소스 ID만 근거 참조로 허용한다. 프로젝트 등록 참조(`operator:project:…`)는 문서 근거로 인정하지 않는다. 응답은 스키마와 별개로 실제 출처·프로젝트 배정·원문 인용을 검증하며, 오류 위치와 잘못된 값을 재검토 피드백으로 전달한다. 분석 실패 후 이어 실행은 기존 목표와 TASK 번호를 유지해 재분석한다.

웹 등록은 설치 프로젝트 후보 목록에서 선택하거나 직접 입력한 기존 폴더를 카탈로그에 추가한다. 후보는 알려진 작업 위치에서 설치 표시를 확인한 결과이며 중앙 등록부나 전체 디스크 목록이 아니다. 요청 실행기가 기본 근거와 준비 상태를 확인하지만 code-agent 설치·PC 신뢰·권한을 자동 승인하지 않는다. PC 신뢰와 페어링은 사람이 화면이나 TTY에서 확인한 경우에만 하며 실행기·AI 계획·복구 경로는 하지 않는다. 대시보드는 실행 터미널을 종료하면 멈추지만 이미 접수한 요청의 별도 실행기는 유지된다. 연결 오류와 화면 기능은 [대시보드](ui.md)를 따른다.

일괄 업데이트의 설치·빌드·릴리스 관리는 code-agent의 공개 CLI에 맡긴다. 설치 호출은 저장소 밖 임시 폴더에서 수행하며 호스트 표지·런타임 강제 환경값을 전달하지 않는다. 설치 가능 여부와 오류 사유는 code-agent 응답을 따른다. 사람이 확인한 문구의 해시를 설치와 프로젝트별 적용에 각각 사용하고, 설치 성공 후에도 적용 확인을 기다린다. 확인 대기는 서버 재시작 뒤 새 적용 미리보기로 이어간다. 적용 직전 잠금·작업 상태를 다시 확인하고 완료 후 릴리스 ID를 대조한다. 현재 설치본 적용은 기존 공개 명령을 유지한다.

계약 인계는 소스 검사·문서 해시·반영 커밋을 대조하고 후속 담당의 첫 배정 전에 `planning contracts`로 등록한다. 형식과 한도는 [검증 계약](live-verification.md)을 따른다. host 선택은 [요청 host와 교차 검증](ai-planning.md#요청-host와-교차-검증)과 [관리 실행 규칙](code-agent-control.md#역할과-적용-조건)을 따른다. 개발 실행은 code-agent 관리 계약으로 통일하며 CLI 배정·계속 실행에는 `--control`이 필요하다.

## 남은 작업

1. 실제 모델의 실패 수정·재계획·프로세스 중단·재부착을 격리 저장소에서 연속 검증한다. 정상 흐름 성공과 자동 회귀만으로 이를 대신하지 않는다.
2. 자유 목표의 AI 계획 생성부터 검증 계약 연결·개발·통합 완료까지 한 번에 실행한다. 현재 전체 흐름 시나리오는 고정 master 계획으로 시작한다.
3. 실제 Codex 모델의 전체 개발 흐름과 호스트 전환 인계를 검증한다. 현재 관리 실행의 시작·thread 확정·재개·재부착은 실제 감독과 모의 모델로 확인했다.
4. 단계별 산출물·실행 결과 전문·실시간 로그·프로세스 생존 정보, 질문과 무관한 실행 중지, 재계획 수동 채택 화면을 제공한다. 현재 타임라인은 수집된 관측·이벤트 범위다.
5. 원격 러너·운영 예산·프로젝트 도메인/근거 자동 갱신과 설치·진단·배포 패키징을 보완한다. 공개 npm·단일 실행 파일 배포는 제공하지 않는다.
6. 사용자의 실제 PC 키 저장소에서 화면 PC 신뢰와 제어 연결로 실제 프로젝트를 연결한다. 현재는 실제 브라우저·code-agent 빌드와 격리 키 저장소로 신뢰부터 연결까지 확인했다.
7. 요청 host의 교차 검증(주 host 생성·다른 host 검토)을 실제 Claude·Codex 모델로 시험해 반려 기준과 재생성 품질을 확인한다. 현재 반려·승인·검토 실패 처리는 모의 AI로, 요청별 host 접수는 실제 code-agent 감독과 모의 Codex 모델로 확인했다.
