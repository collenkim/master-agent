# AI 오케스트레이션

사용자 목표를 프로젝트별 작업으로 분해하고 실행·검증·인계를 조정한다. 제품 목표는 [요구사항](requirements.md), 코드 구성은 [시스템 구조](architecture.md), 미구현 범위는 [남은 작업](implementation.md#남은-작업)을 따른다.

## 목표와 근거

Mission은 요청 원문·완료 조건·프로젝트 범위·접수 키·실행 모드를 가진다. 요청 접수 시 범위를 고정하고 해당 범위의 프로젝트 근거를 수집한다. 그룹 구성원 모두에 작업을 배정할 필요는 없지만 범위 밖 프로젝트를 조용히 추가하지 않는다.

AI 계획은 수집한 정책·계약·코드·테스트를 근거로 프로젝트 역할과 작업 순서를 제안한다. 근거 ID·인용·버전과 프로젝트의 도메인·기능·기존 계획을 검증한다. 부족한 정보는 재검토하거나 질문으로 남긴다. 수집·분석·교차 검증은 [AI 계획](ai-planning.md)을 따른다.

## 계획과 작업 계약

계획 버전은 목표와 프로젝트 버전에 결속한다. 활성화 전에 미해결 항목, 중복 ID, 범위 밖 배정, 잘못된 의존 관계와 순환을 거부한다.

| 작업 필드 | 역할 |
| --- | --- |
| id, kind | 작업 식별자와 analysis / contract / implementation / verification / integration 종류 |
| projectId, domain | 담당 프로젝트와 도메인 |
| goal, rationale | 목표와 배정 근거 |
| dependsOn | 선행 작업 ID |
| criteria | 목표의 완료 조건 ID |
| allowedChanges, exclusions | 허용·제외 변경 범위 |
| outputs, verification | 요구 산출물과 검증 설명 |
| requiredCapabilities, references | 실행 기능과 등록된 근거 |
| planAcknowledgements, coordination | 프로젝트에 기존 계획이 있을 때의 대조·조정 |

모든 완료 조건에 검증 작업이 필요하며 일반 작업의 조건은 후행 검증에 연결해야 한다. 여러 프로젝트가 참여하면 전체 작업을 선행 관계로 묶는 통합 검증이 필요하다. 실행 전에는 [독립 검증 계약](live-verification.md)을 등록한다.

## 실행 흐름과 상태

```text
접수 → 근거 수집·분석 → 계획 검증·활성화
  → 실행 가능한 작업 배정 → 관측·질문·판단
  → 독립 검증·반영 대조 → 선행 계약 인계 → 후속 작업
  → 통합 검증·완료 조건 판정
```

Mission 상태는 `received`, `analyzing`, `planned`, `waiting-decision`, `executing`, `paused`, `blocked`, `succeeded`, `simulation-complete`, `cancelled`다. 작업·시도·그래프 상태와 화면의 progress 표시는 별도로 관리한다.

배정 시 선행 결과·계획과 프로젝트 버전·검증 계약·프로젝트 잠금을 확인한다. 독립 프로젝트의 준비된 작업은 병렬 진행한다. 실패나 일반 복구 보류의 영향을 받지 않는 작업은 계속할 수 있으며, 중대한 판단·재계획 보류는 목표 전체에 적용한다.

LangGraph는 체크포인트와 실행 임대로 흐름을 관리한다. 외부 실행 전 시도와 판단을 저장하며 code-agent가 접수·소유권을 검증한다. 재시작 시 같은 실행 ID로 재부착하고 미확인 실행을 자동 중복 접수하지 않는다. 상세 내용은 [실행 구조](langgraph.md)와 [관리 통신 계약](code-agent-control.md)을 따른다.

## 실패·재계획·사용자 제어

| 상황 | 처리 |
| --- | --- |
| 검증된 범위 내 실패 | 근거를 분석해 같은 작업의 수정·재검증을 수행한다. |
| 실행·반영 여부 미확인 | 저장된 반환·원격 상태·산출물을 대조한다. 확인 전 중복 배정을 막는다. |
| 계약·범위 변경 필요 | 기존 실행을 정리한 뒤 재계획 인계와 근거 수집을 수행한다. |
| 인계 뒤 파일·HEAD 변경 | stale-replan으로 막고 명시적 replan-refresh 후 재분석한다. |
| 사람 판단 필요 | 질문과 근거를 보존하고 해당 응답 경로에서 처리한다. |

새 계획을 활성화할 때 이전 성공 증거를 그대로 재사용하지 않는다. 새 계획의 검증 계약과 인계 조건을 다시 확인한다. [복구](recovery.md)·[재계획](replanning.md)·[중단 처리](interruption.md)의 조건을 따른다.

`mission pause`는 새 배정을 멈추고 기존 실행·잠금을 보존한다. `mission stop`은 특정 관리 실행의 종료를 요청한다. `mission cancel`은 실행 중(`running`) 시도가 없는 목표를 `cancelled`로 마감한다. 실행 중 시도는 stop 또는 unknown으로 먼저 정리한다. 취소는 모든 목표 잠금과 분석·복구 보류를 해제하고 결정·사유를 기록하며 작성한 코드를 되돌리지 않는다. 이미 종료한 목표의 재취소는 거부한다.

## 판단과 권한

AI 제안이나 완료 문장만으로 상태를 변경하거나 검증을 통과시키지 않는다. 판단을 먼저 저장하고 출처·허용 범위·계획·계약·원격 상태를 대조한 뒤 실행한다. 모델 출력은 데이터이며 권한 확대 지시로 사용하지 않는다.

위임 가능한 판단과 사람에게 넘길 판단은 [위임 판단](code-agent-control.md#위임-판단)을 따른다. 사람 응답은 질문·버전·문맥에 결속하고 원래 처리기로 전달한다. 응답 접수·적용·실행 재개는 별도로 확인하며 [공통 요청함](dashboard-interactions.md)의 전송 계약을 따른다.
