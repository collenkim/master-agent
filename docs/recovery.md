# 검증 실패 분석과 범위 내 자동 복구

## 실행 임대 복구

그래프와 요청 실행기는 마지막 heartbeat를 기준으로 기본 10분 TTL을 적용한다. 같은 호스트에서 pid가 살아 있으면 TTL과 관계없이 유효하다. 다른 호스트이거나 생존을 확인할 수 없는 프로세스는 TTL 만료 뒤 회수하고 기록을 남긴다. 요청 실행 중에는 heartbeatAt을 30초마다 갱신한다. 호스트명 변경·DB 복사 후 최근 heartbeat가 남았으면 만료 전까지 중복 실행을 막는다.

```powershell
master-agent mission unlock <목표ID> --revision <목표버전> --confirm
master-agent request reset <요청ID> --revision <요청버전> --confirm
```

두 명령은 최신 버전과 명시적 확인을 요구하며, 같은 호스트의 살아 있는 프로세스가 있으면 거부한다. `mission unlock`은 목표 그래프 임대를 회수하고 기존 graph_runs를 interrupted로 마감한다. `request reset`은 같은 요청의 실행 소유자를 해제하고 queued로 되돌린다. 두 명령 모두 결정과 이벤트를 남기며 자동으로 개발을 시작하지 않는다. 요청은 이후 `request run` 또는 기존 이어 실행 경로로 재개한다. 실제 개발 시도와 프로젝트 잠금은 별도 정지·관측·복구 절차로 확인한다.

현재 단계는 실제 검증 실패를 AI가 분석하고, 원인·근거·대안·수정 단계를 저장한 다음 기존 작업 범위에서 실행하는 흐름이다. 운영 예산·배포 정책은 확정하지 않는다.

## 실행 흐름

1. 독립 검증의 종료 코드, stdout·stderr(각 최대 16000자), 전체 출력 해시를 보존한다. 시간 초과나 파일 변형은 `unknown`으로 분리하며 자동 복구하지 않는다.
2. 실패 시도·검증 기록·현재 Git 트리·계획·기존 계약·code-agent 상태를 묶는다. 이미 수집 대상으로 지정한 코드만 현재 내용으로 다시 읽는다. 코드 읽기는 파일당 64KiB·합계 256KiB로 제한하며 비밀 경로와 링크는 제외한다.
3. AI가 구조화된 복구안을 반환한다. 없는 근거 인용, 허용 파일 밖 수정, 모호함이 남은 실행 제안은 재검토한다. 검토는 최대 2회이며 오류가 남으면 실행하지 않는다.
4. 판단을 저장한 뒤 현재 파일·정책·프로젝트 버전·선행 산출물·원격 상태를 대조한다. 분석 중에는 해당 시도의 계속 실행과 검증을 막는다. 일시 정지와 버전 충돌도 실행을 차단한다.
5. `repair`는 기존 Claude 세션에 수정 계획과 기존 검증 계약을 전달한다. `reverify`는 일시적 실패에 대해 기존 검증 명령을 다시 실행한다. 수정 결과는 이후 독립 검증과 인계를 거쳐야 완료된다.

| 판단 | 동작 |
| --- | --- |
| repair | 기존 허용 경로 안에서 기존 세션 계속 실행 |
| reverify | 파일과 검증 계약을 유지하고 독립 검증 재실행 |
| needs-context | 부족한 근거·질문 기록, 추가 근거를 받아 재분석 |
| replan | 변경 이유와 권고 저장, 신규 배정 보류 |
| needs-human | 중대한 문제의 질문·권고 저장, 판단 대기 |

code-agent의 요구 확정·계획 승인·미응답 질문·동의·임대는 기존 절차를 따른다. 복구안의 실행 허용과 code-agent 동의는 별개다. 관리 실행은 사람이 준 grant 안에서 routine 동의·답변을 [위임 판단](code-agent-control.md)으로 적용한다. 권한 밖 판단은 기존 사람 응답 절차를 따른다.

## CLI

```powershell
master-agent mission recover <목표ID> <시도ID> --revision <버전> --expect-state <상태버전> --cli C:/IdeaProjects/code-agent/dist/agent/cli.js --provider claude --control
master-agent mission drive <목표ID> --cli C:/IdeaProjects/code-agent/dist/agent/cli.js --provider claude --control
master-agent mission show <목표ID>
```

`recover`는 `--context "추가 관측이나 결정 근거"`로 정보를 받아 재분석할 수 있다. 이는 code-agent 승인이나 변경 범위 확대 권한이 아니다. 호출은 현재 mission revision과 원격 상태에 결합되며 추가 근거를 복구 기록에 보존한다. 파일이 바뀌었다면 먼저 현재 파일을 독립 검증해야 한다.

`drive/advance`에 provider를 지정하면 확인된 검증 실패를 자동 분석한다. 지정하지 않으면 실패에서 멈춘다. 같은 실패 기록은 자동으로 한 번만 분석하며, 동일 시도의 자동 복구 실행은 최대 2회다. 이는 무한 반복 방지 장치이며 운영 정책의 확정값이 아니다. 일반 복구 보류는 해당 프로젝트와 의존·근거 참조 작업의 신규 배정을 멈추며 독립 프로젝트는 계속 진행한다. 중대한 판단과 재계획 보류는 목표 전체에 적용한다. 보류된 복구는 `recover`로 명시적으로 재분석한다. 상세 규칙은 [자동 진행 보완](autonomous-progress.md)을 따른다.

`mission show`의 `recoveries`에는 분석 회차, 원인, 수정 단계, 인용, 위임 판정, 실행 시각과 오류가 표시된다. `decisions`와 이벤트로 판단이 호스트 실행보다 먼저 저장됐는지 확인할 수 있다.

호스트 실행·요청 실행기 오류의 코드는 상태에 남기고 원문은 DB·화면·모델 입력에 전달하지 않는다. 진단용 코드와 스택 첫 줄은 서버 표준 오류와 DB 옆 `request-logs/<요청ID>.log`에만 기록한다. 로그 기록 실패가 기존 실행 결과를 바꾸지는 않는다.

## 현재 경계와 다음 단계

범위 변경 시 실행 중인 작업을 자동 폐기하거나 새 계획으로 덮어쓰지 않는다. `replan` 제안은 [재계획 인계](replanning.md)로 연결한다. 외부 작업 종료·변경 보존·잠금 정리 후 근거를 재수집하고 새 계획을 활성화한다. 기존 검증 계약은 새 계획에서 다시 등록해야 한다.

프로세스 중단으로 분석 또는 실행 의도만 남은 경우 자동 재제출하지 않는다. [반영 기록·관측 복구](delivery-reconciliation.md)는 저장된 호스트 반환이 있는 경우만 처리한다. 읽기 전용 분석 예약은 [분석·검증 중단 처리](interruption.md)로 정리한다. 통신 계약 경로는 실행 중 정지·취소·재부착을 지원하며 미확인 실행의 일반 복구와 구분한다. 복구 회귀 시험은 모의 모델·호스트와 실제 파일·Git·Node 검증을 사용한다. 실제 모델의 정상 전체 흐름은 통과했으며, 실패 복구 전체 사이클의 실제 모델 평가는 후속 범위다([검증 기록](verification.md)).
