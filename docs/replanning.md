# 실패 작업의 재계획 인계

범위 내 수정으로 해결하지 못해 `replan`으로 보류된 실패 작업을 최신 근거의 새 계획으로 연결한다. 외부 code-agent 작업을 강제로 종료하거나 변경을 되돌리지 않는다.

## 순서

1. 현재 계획·실패 시도·복구 제안·프로젝트 잠금을 대조한다. 다른 미정리 live 시도가 있으면 보류한다.
2. 목표에 포함된 모든 프로젝트에서 외부 작업과 접수가 없고, 질문·동의·임대가 정리됐는지 조회한다. `no-work`만으로 반영 승인을 추정하지 않는다.
3. 실패 프로젝트의 파일과 HEAD가 복구 판단 당시와 같은지 검사한다. 변경이 추가됐으면 인계하지 않는다.
4. 판단을 기록하고 기존 수집 목록의 근거를 다시 읽는다. 프로젝트 카탈로그 갱신, 인계 기록, 실패 시도의 `abandoned` 처리, 잠금 해제를 한 트랜잭션으로 저장한다. 중간 오류는 모두 롤백한다.
5. 원래 목표·대상·완료 조건, 이전 계획, 실패 이유·권고와 최신 코드를 AI 분석에 전달한다. 분석 동안 수집 목록 밖 파일까지 전체 Git 트리와 HEAD를 대조한다. 다른 master 작업의 잠금도 새 계획 적용을 막는다.
6. 검증을 통과한 새 계획을 활성화하고 모든 작업을 대기로 시작한다. 이전 계획·시도·실패 검증·인계 기록은 보존한다. 이전 검증 계약과 완료 증거는 새 계획에 자동 이식하지 않는다.

`abandoned`는 기존 시도를 새 계획으로 넘겼다는 뜻이며 성공·커밋·배포 완료가 아니다. 작업 파일을 수정하거나 삭제하지 않고 해시와 당시 원격 상태를 인계 기록으로 남긴다. 파일 백업·롤백 기능은 제공하지 않는다.

## 사용

```powershell
master-agent mission replan <목표ID> <실패시도ID> --revision <현재버전> --expect-state <상태버전> --provider claude --control
master-agent mission show <목표ID>
```

provider를 생략하면 인계·근거 재수집까지만 수행하고 실행 보류 상태를 유지한다. 이후 `mission analyze`로 분석할 수 있다. provider를 지정한 `drive/advance`도 재계획 보류를 발견하면 같은 경로를 사용하며, 외부 종료 전에는 대기한다. 새 계획의 검증 계약은 배정 전에 다시 설정한다. 등록된 [검증 템플릿](live-verification.md#재사용-검증-템플릿)이 정확히 하나 일치하면 자동 연결하고, 그 외에는 작업별 등록이 필요하다. 이전 성공 증거는 재사용하지 않는다.

AI 호출 실패나 정보 부족은 인계된 변경을 보존하고 계획 실행을 보류한다. 최신 revision으로 `mission analyze`를 재호출할 수 있다. 인계 후 파일·HEAD가 달라지면 `stale-replan`으로 차단하며 아래 재동기화를 거쳐야 한다.

`mission show`의 `replans`에는 인계 판단, 실패 시도·복구 ID, 이전 계획 버전, 프로젝트별 트리, 원격 종료 상태, 재수집 스냅샷이 표시된다. 계획 분석 기록에도 해당 인계 자료가 연결된다.

## 인계 이후 재동기화

```powershell
master-agent mission show <목표ID>
master-agent mission replan-refresh <목표ID> --revision <현재버전>
master-agent mission analyze <목표ID> --revision <갱신된버전> --provider claude
```

재동기화는 인계가 끝난 재계획 대기 목표에만 허용한다. 목표 버전과 모든 대상의 잠금을 검사하고 현재 트리·HEAD를 다시 수집한다. 기존 근거 목록도 다시 읽으며 수집 전후 파일이 바뀌면 전체 갱신을 롤백한다. 이전 인계 레코드는 보존하고 `replanContext.treeChanges`에 프로젝트별 이전·새 digest, HEAD와 변경 파일별 해시를 누적 기록한다. 결정 레코드에도 이번 변경 내역을 남긴다.

재동기화 후 상태는 최초 인계와 같은 `blocked`이며 `planningHold`를 유지한다. `mission analyze`로 새 계획을 검증하기 전에는 실행하지 않는다. 분석 프롬프트는 변경 내역을 "인계 이후 바뀐 파일" 데이터로 전달하며 지시 권한을 부여하지 않는다. 재동기화 없이 분석을 반복하거나 재동기화 뒤 파일이 다시 바뀌면 계속 차단한다. `mission show`의 `nextAction`에 최신 revision을 포함한 재동기화 명령을 표시한다.

## 검증 경계

회귀 테스트는 임시 Git 저장소의 실제 파일·검증 명령과 통제된 외부 상태·AI 응답을 사용한다. 관리 실행은 code-agent가 접수 시 상태·소유권·임대를 한 잠금 안에서 대조하고, grant 범위의 위임 판단을 지원한다([통신 계약](code-agent-control.md)). 실제 모델의 정상 전체 흐름과 실패 후 재계획 품질 평가는 구분하며 후자는 후속 검증이다.
