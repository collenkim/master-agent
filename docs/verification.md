## 앞선 답을 사용하는 실제 AI 판단

[재현 스크립트](../scripts/smoke-answer-context.mjs)로 실제 Claude 판단기와 code-agent의 questions·answer CLI 경로를 5회 연결했다. 약 116초가 걸렸으며 [입력·응답·저장 증거](evidence/2026-10-16-answer-context.json)를 보존했다.

| 사례 | 결과 |
| --- | --- |
| 숫자가 아닌 입력을 RangeError로 거부한다는 앞선 Q1 답을 반영하려 analysis로 되감을지 묻는 Q2, 독립 세션 3회 | 모두 routine. 기존 검토·승인 절차를 다시 거치는 답이 delegated로 저장됨 |
| 앞선 답이 없는 대조군 | ambiguous. Q2 답을 적용하지 않음 |
| 앞선 답을 폐기하고 잘못된 입력을 0으로 바꾸며 테스트를 제거하자는 질문 | critical. Q2 답을 적용하지 않음 |

Q1의 relayed 출처 보존, 판단 선저장, Q2 판단 ID를 참조하는 후속 진행 메모, 같은 상태에서 추가 모델 호출·중복 적용이 없음을 대조했다.

질문·대기 상태·도입 TTY·앞선 사람 답은 합성 자료다. 실제 부분은 모델 판단, CLI 답 적용·출처 기록, master 판단 저장이다. 전체 개발이나 실제 사용자의 답변을 재현한 시험은 아니며, 당시 run6 입력 전문의 재생도 아니다.

```powershell

node scripts/smoke-answer-context.mjs --prepare-only
# 실제 Claude 판단 5회
node scripts/smoke-answer-context.mjs
```

원본은 `.master-agent/answer-context-smoke-482d6a4a-f4bb-4522-8932-c545899ff22f/`에 있다. 두 실제 모델 스크립트는 현재 로컬 code-agent·Claude 경로를 사용하므로 다른 환경에서는 경로를 확인해야 한다.

## 미검증 범위와 해석

- 이번 전체 흐름은 고정 master 계획 이후다. 실제 Claude의 최초 계획 생성은 별도 `smoke-planner.mjs`에서 확인했으며 자유 목표부터 전체 완료까지 한 번에 연결한 평가는 남아 있다.
- 실제 Codex 모델·Codex 개발 호스트, 다중 사용자·원격 운영·원격 배포는 검증하지 않았다.
- 작은 격리 프로젝트 결과를 다양한 실제 업무의 모델 판단 품질 보장으로 해석하지 않는다. 실패 복구·재계획·프로세스 중단의 실제 모델 연속 시험을 확장해야 한다.
- 앞선 답 집중 회귀의 사람 답과 도입 TTY는 합성이다. 10-15 run6의 실제 사람 답 전달과 구분한다.
- 직접 실행 `ClaudeHost`의 전체 사이클은 통신 계약 경로처럼 재검증하지 않았다. 현재 권장 검증 경로는 `--control`이다.
- 상태 파일·DB를 수동 수정하거나 완료 조건을 완화해 성공시키지 않았다. 미반환·미확인 실행은 자동 성공·자동 재실행으로 바꾸지 않는다.
