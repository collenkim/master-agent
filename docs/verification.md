## code-agent 통신 계약 연동 검증

[code-agent 통신 계약 연동](code-agent-control.md)은 세 층으로 나눠 확인했다. 앞의 둘은 모델을 부르지 않는다.

- 모의 시험 `tests/control.test.mjs`(19개): 통신 계약을 흉내 낸 전송과 가짜 판단기로 두 프로젝트의 위임 판단 → 독립 검증 → 위임 반영 → 인계 → 통합 완료, 판단 기록 선행, critical·ambiguous·권한 없음·준비하지 않은 동의의 사람 이관, 검증 전 반영 판단 금지, 위임 영수증 결합, 재부착 중복 없음, commandId 충돌·이벤트 재동기화, 정지 대상 제한, 독립 프로젝트 진행과 의존 작업 대기, 실제 AI 시험에서 찾은 결함의 회귀(통신 계약 실행 프롬프트의 기대 상태 재대조 제거와 독립 검사 경계, 반영 판단의 문서 변경 후보, 선행 반영 커밋 기준, 반영 단계에서만 하는 독립 검증과 반영 단계를 떠난 검증된 시도의 계속 실행, 위임 수정 요청 뒤 같은 세션의 재준비, 이어 실행 접수 거부의 막힘 기록, 반영 확인 수정 요청 뒤 재준비와 재검증, 선행 증거 요약 프롬프트)를 본다. `tests/engine.test.mjs`는 다른 CLI가 쓰는 동안 같은 DB의 트랜잭션이 잠금 해제를 기다리는지 본다.

### 실제 AI 다중 프로젝트 사이클

조건: Windows, Node.js 24.19.0, Claude CLI 2.1.300(모델은 CLI 기본값). 임시 git 프로젝트 둘(price-core·invoice-app)에 code-agent를 설치하고 `mission drive --control --provider claude`로 돌렸다. 개발 세션과 위임 판단기 모두 실제 Claude다. 작업은 할인 함수(price-core)·합계 함수(invoice-app)를 독립으로 구현하고 결제 합계(invoice-app)로 통합하는 셋이며, 완료 판정은 프로젝트 밖 독립 검사 스크립트와 프로젝트 테스트다. 사람의 TTY 단계 셋(공통 문서 확정·code-agent `master enable`·`master grant`)은 시험 하네스가 흉내 냈고 기록에 '사람 TTY 흉내(실제 사람 확인 아님)'로 남는다. 작업별 확인 요청과 업무 질문은 흉내 내지 않았다. 시험별 경위·근거는 code-agent 저장소의 `doc/reviews/2026-10-15-master-control.md`와 `doc/reviews/evidence/2026-10-15-master-control.json`에 있다.

- run2(결함 찾기): 실행 프롬프트의 기대 상태 재대조, 끝 상태 뒤 이벤트 누락, DB 잠금 대기 0, 반영 판단의 문서 변경 후보, 독립 검사·범위 제약을 code-agent 수락 기준으로 옮긴 일, 선행 반영 커밋 기준을 찾아 고쳤다. price-core는 위임 계획 승인 → 구현 → master 독립 검증 통과까지 갔고, 두 작업이 사람 이관에서 멈췄다(완료 아님).
- 실제 Claude 실행 정지 시험: 협력 정지(요청 접수와 정지 확인 분리, 프로세스 종료·변경 없음), 같은 세션 재개, 실행 중 제어권 인계(협력 정지 확인 뒤 이전, 이전 소유자·인수 전 새 제어자 거부), 강제 취소(프로세스 종료, 작업 트리·HEAD 그대로).
- run3: price-core는 사람 개입 없이 위임 승인 셋 → 독립 검증 → 위임 반영 커밋 → 인계까지 끝났다. invoice-app에서 반영 단계 전 독립 검증, 위임 수정 요청 뒤 이어 가기, 이어 실행 접수 거부의 기록 결함을 찾아 고쳤고, 시도가 unknown 으로 멈췄다(완료 아님).
- run4(세 결함 수정 뒤 처음부터): 독립 작업 둘(할인·합계)이 사람 개입 없이 위임 승인 → 반영 단계 독립 검증 → 위임 반영 커밋 → 인계까지 끝났다. 판단기가 할인의 반영 확인을 ambiguous 로 보고 수정 요청을 보냈을 때 검증된 시도에 이어 가기가 없던 결함과, 통합 작업(결제 합계)의 프롬프트가 선행 증거를 통째로 실어 code-agent 접수 한도(20000자)를 넘은 결함을 찾아 고쳤다. 통합 작업은 시작하지 못했다(완료 아님).
- run5(run4 의 결함 둘 수정 뒤 처음부터): (실행 중)

## 검증하지 않은 범위

실제 Codex 모델 호출(개발 호스트·계획·위임 판단기), 다중 사용자·원격 운영 환경은 검증하지 않았다. 실제 AI 시험은 작은 임시 프로젝트 둘의 작업 셋이며, 실제 모델의 재검토·위임 판단 품질을 다양한 업무에서 본 것은 아니다. 판단기가 critical·ambiguous 로 사람에게 넘기는 경로는 모의 시험으로만 확인했다 — 실제 AI 시험에서 사람에게 넘어간 판단은 없었다. 통신 계약 없이 쓰는 직접 실행 호스트(`ClaudeHost`)는 세션에 기대 상태를 다시 대조시키므로 실행 중 상태 버전이 바뀌면 멈출 수 있다 — 통신 계약 호스트에서 찾아 고친 문제이며 직접 호스트로는 실제 AI 사이클을 다시 돌리지 않았다. 통신 계약의 첫 실행(start) 접수가 거부되면 시도는 unknown 으로 남고 운영자가 원인을 확인한다(자동 재실행하지 않는다). 자동 재검토와 세션 재개의 제어 흐름은 가짜 모델·자식 프로세스로도 검증했다.

## 기술 선택 근거

현재 환경에서 Node.js 내장 SQLite의 트랜잭션과 조회 동작을 직접 확인해 저장 어댑터에 사용했다. 버전별 안정성과 API 차이는 [Node.js SQLite 문서](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)를 기준으로 확인한다. 테스트는 [Node.js test runner](https://nodejs.org/docs/latest-v24.x/api/test.html)를 사용한다. AI 연결은 Codex·Claude CLI 어댑터를 유지한다. 실행 오케스트레이션에는 LangGraph JS를 도입했으며 모델 API SDK는 도입하지 않았다.
